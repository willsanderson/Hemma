# Hemma v2.0.3

A maintenance release on top of v2.0.2. No configuration changes are needed, though light popups look and behave a little differently, and light cards need fewer variables than before. See [Upgrading](#upgrading) if you have customized the theme.

---

## Fixes

- **Mobile Scenes row was clipped to half the screen.** Set up from the commented example in `hemma_mobile.yaml.example`, the scenes strip rendered one chip and then cut off mid-screen, with empty space beside it. The row needed `full_width: true` on the card, which the example omitted, so it was placed in one of the two mobile grid columns and clipped at that column's edge rather than at the screen edge. `hemma_scene_row` is now registered in the row layout table alongside the weather, badge, header, sensor chip and Now Playing rows, so it spans both columns on its own. Reported by @SH1FT-W.
- **Scenes setup is much simpler.** Four separate requirements are gone. The row no longer needs `full_width: true`, the Scenes overlay builds its own contents so `room: Scenes` is all it takes, the section header derives its filter behaviour from `name: Scenes` instead of needing `mobile_filter_category: unfiltered`, and the instruction to add `room_scenes` to `input_select.hemma_mobile_filter` was wrong because that option already ships in `packages/hemma_helpers.yaml`. Scenes now looks like every other section: a template, a name, and your scene entities. Existing configurations keep working, since an explicit `full_width` or `sections:` still wins.
- **Energy group badge now highlights when expanded (desktop and tablet).** Tapping Energy opened its sub-badge row but left the group badge itself dark, unlike Climate, Lights, People and Security. Room cards point the Energy badge's `entity` at the room's power sensor so hold still opens that room's energy popup, and the badge's active-state check was reading that sensor rather than the expanded-row helper. It now reads the helper through a new `row_entity` variable on `hemma_badge_energy_group`, defaulting to `input_select.hemma_expanded_row`; the mobile filter row overrides it with `input_select.hemma_mobile_filter`. Mobile was unaffected and behaves as before.
- **Badge text sat too close to the right edge on tablet.** Right padding goes from 11px to 14px.
- **Tablet badge sizing is tunable again.** The tablet breakpoint in `hemma_badge_base` hard-coded its icon size, height, padding and font size as `:host { ... !important }` inside each badge's shadow root, which beat the matching block in the theme, so the `badge-*-tablet` variables had no effect. Those four values now read the theme variables, keeping the previous numbers as fallbacks. `badge-gap-tablet`, `badge-col-gap-tablet` and `badge-btn-size-tablet` were never overridden and already worked.
- **Light popups no longer open near full screen on mobile when they hold a single light.** The mobile height lock is deliberate for grouped light popups: tapping a room pill there hides and shows whole sections, and because the sheet slides up from the bottom, a self-sizing popup would jump up and down on every room switch. Popups without that pill row, a single light or a flat list with no room grouping, have nothing that can change their height, but were inheriting the lock anyway and opened at 92% of the screen height around one tile. They now size to their content, like the Fan and Cover popups. Room switching in grouped popups is unchanged. Reported by @macmonty.
- **A room's light card and its light badge now open the same popup.** The light badge already promoted a room group to the larger group it belongs to, so holding it opened the whole-home popup with a pill per room and that room selected. The room's light *card* did not, so the same room had two different popups unless you set `group_entity` by hand on every card. That promotion now lives in the popup itself and both surfaces share it. Nothing to configure: if the group a card points at sits inside a larger one, its popup opens on the larger group with this room selected. Set `popup_group: none` to keep a card's popup to its own lights. One knock-on effect on mobile: a room light card's popup now carries the room pills, so it uses the fixed sheet height described above rather than sizing to its content.
- **A single-room light popup is titled with its room.** The popup's `room_name` defaulted to `Home`, and a default beats every fallback beneath it, so a light card's popup was headed `Home` no matter which room it covered. It now falls back to the group's **area** first, which matters because group helpers are usually renamed to a bare "Lights", then to `Home` for a multi-room popup. Whole-home popups still read `Home`, and an explicit `room_name` still wins.
- **More room above the tiles in a single-room light popup.** The flat grid sat `10px` below the header, close enough that the first row of lights crowded the title and the power button. Multi-room popups never showed this, because the room pill row separates the two with `26px`. The flat grid now uses that same spacing, so both layouts sit identically under the header.
- **The example dashboards listed `scene_order` on every light card, where it did nothing.** The light popup hides scenes by default, so ordering them had no effect until `show_scenes: true` was also set, which the examples never mentioned. Both examples now show `show_scenes` and `scene_order` together as one commented block on the All Lights card, and the room cards carry neither that nor `popup_group`. A room's light card is now three lines. Reported by @LuisEvang.
- **`scene_scope` is gone.** It existed only to restore the pre-2.0.2 behaviour of listing every scene in a light popup, including ones touching none of that popup's lights. Since scenes now have their own row and Scenes page, that is what those are for, and the popup always lists just the scenes covering its own lights. The variable was an option on an option, reachable only after opting into `show_scenes`, so it is unlikely anyone set it. If you did, the popup's scene list narrows; nothing errors.
- **`group_entity` is now `popup_group`.** It only ever affected the popup, never the card face, and the old name did not say so. It is now an override rather than something you set on every room card, since the promotion above covers the common case. `group_entity` still works, so nothing needs changing.

## Theme

Because the four tablet variables were inert, their values in `themes/hemma/hemma.yaml` had drifted from what tablets actually rendered, and they have been resynced. On a stock install, this changes nothing beyond the padding fix above.

New variable: `badge-media-pad-v-tablet` (default `7px`). The media badge's vertical padding is deliberately matched to the group badges' and was previously hard-coded, so changing the vertical values in `badge-padding-tablet` would silently desync it.

## Upgrading

`smart-row.js` and `filter-overlay.js` both changed. Bump the `?v=` cache buster on both entries in Settings > Dashboards > Resources, then hard refresh. The Companion app caches `/local/` for weeks, so without this the Scenes fix will not reach your phone.

Reload themes and hard refresh. A plain dashboard refresh is not enough for the theme change.

If you have customized any of the four tablet variables in a theme fork, check your tablet after upgrading. Those customizations were being ignored and will take effect for the first time.
